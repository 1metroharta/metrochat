# Push-уведомления в MetroChat без Cloud Functions

Документ описывает варианты, которые **не внедрены** в b5.1 — это экспертные предложения.
Сейчас приложение показывает уведомление только когда вкладка открыта (`Notification` + service worker).

## Почему нельзя просто «включить FCM»

Web Push в браузере требует трёх вещей:

1. `PushSubscription` от пользователя (ключи VAPID) — хранится в `push_subs/{uid}`.
2. Отправителя, который подписывает запрос приватным VAPID-ключом.
3. Для Chrome/FCM — OAuth-токен сервисного аккаунта.

Приватный ключ нельзя держать в `index.html` или в клиенте: любой сможет рассылать push от имени MetroChat.
Cloud Functions как раз и были «отправителем». Без них нужен **крошечный внешний отправитель** — не база,
не сервер приложения, а 30–60 строк кода на бесплатном edge-раннере.

## Вариант A — Cloudflare Worker + Web Push (рекомендую)

```
Клиент ──(sendMessage)──► RTDB outbox/{chatId}/{msgId}
                              │
Cloudflare Worker (cron 1 мин) ─┘ REST-чтение outbox + push_subs
                              │
                    Web Push (VAPID) / FCM HTTP v1
```

- **Плюсы:** Cloud Functions не нужны, бесплатный тариф Cloudflare Workers (100 000 запросов/сутки),
  рассылка фактически безлимитная при разумном throttle, ключи лежат только в Worker Secrets.
- **Минусы:** нужен аккаунт Cloudflare и домен/поддомен для воркера; RTDB читается по REST
  (`https://<db>.firebaseio.com/outbox.json?auth=<token>`), значит нужен сервисный токен с доступом
  только к `outbox`, `push_subs` и `presence`.
- **Защита:** Worker принимает от клиента `POST /notify` с Firebase ID-token, сам проверяет токен
  (JWKS Google), лимитирует 20 уведомлений в минуту на отправителя, ставит TTL 5 минут и не дублирует
  по `msgId`. Пользователь может отписаться (`push_subs/{uid}` удаляется, инвалидная подписка удаляется
  по ответу 410).
- **Стоимость:** 0 ₽ на бесплатном тарифе, ~5–15 мс CPU на уведомление.

## Вариант B — Deno Deploy / Vercel Edge + Web Push

То же самое, но без Cloudflare: cron-триггер раз в минуту (`Deno.cron`) читает `outbox`.
Плюс — нет привязки к Cloudflare. Минус — меньше бесплатных лимитов на исходящие запросы.

## Вариант C — OneSignal / Novu как внешний отправитель

- SDK подписывает пользователя, REST-ключ хранится на вашем мини-прокси (иначе его украдут из клиента).
- Плюсы: панель, статистика, отписки, поддержка iOS PWA.
- Минусы: зависимость от стороннего сервиса, лимиты бесплатного тарифа (обычно 10 000 получателей),
  данные подписок уходят наружу.

## Вариант D — совсем без сервера

- **Periodic Background Sync** (Chrome Android, установленная PWA): service worker просыпается
  раз в 12–24 часа и читает `user_chats/{uid}.unread`. Уведомление приходит с задержкой — это дайджест,
  а не push. Работает без ключей и без сервера.
- **«Уведомление при возврате»**: при `visibilitychange` показывать сводку непрочитанного. Уже частично
  есть в приложении: счётчик в заголовке вкладки.
- **Локальные уведомления по WebSocket/RTDB**, пока вкладка открыта — работает и сейчас.

## Ограничения, о которых нужно знать заранее

- **iOS:** Web Push доступен только для PWA, добавленной на экран «Домой» (iOS 16.4+), и только после
  явного разрешения. В обычной вкладке Safari push не приходит.
- **Приватный VAPID-ключ и OAuth сервисного аккаунта** — только на сервере. В клиенте им не место.
- **Firebase RTDB не умеет инициировать HTTP-запрос** при записи. Нужен либо cron-опрос `outbox`,
  либо клиентский `POST` в Worker после отправки сообщения (быстрее, но легко потерять при офлайне —
  поэтому cron-подстраховка обязательна).
- **Спам и стоимость:** без лимита на отправителя любой аккаунт сможет «пушить» всем. Лимит в Worker
  и проверка членства в чате обязательны.

## Что нужно, чтобы включить Вариант A

1. Сгенерировать пару VAPID-ключей (`web-push generate-vapid-keys`).
2. Создать Worker с секретами `VAPID_PRIVATE`, `VAPID_PUBLIC`, `FIREBASE_DB_URL`, `FIREBASE_TOKEN`.
3. Добавить в приложение кнопку «Включить уведомления» → `registration.pushManager.subscribe(...)`
   → сохранить подписку в `push_subs/{uid}` (правила: `$uid` пишет только владелец, читает только Worker
   по сервисному токену).
4. Добавить `outbox/{chatId}/{msgId}` в правила: писать может отправитель сообщения, читает Worker.
5. Проверить: два аккаунта, закрытая вкладка получателя, Android Chrome + iOS PWA.

Без шагов 1–2 полноценные push невозможны: браузер не умеет отправлять их сам, а хранить ключи
в открытом клиенте недопустимо.
