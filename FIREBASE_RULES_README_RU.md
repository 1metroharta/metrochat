# Firebase Realtime Database Rules — MetroChat b5.0.3

Файл `database.rules.json` — полный набор правил для Realtime Database. Версия b5.0.3 закрывает публичные узлы, которые раньше были доступны любому авторизованному пользователю.

## Как опубликовать

1. Сделайте резервную копию текущих правил: Firebase Console → Realtime Database → Rules (скопируйте текст в файл).
2. Откройте `database.rules.json` из репозитория и вставьте его содержимое вместо старых правил (или запустите `DEPLOY_RULES.bat`).
3. Нажмите **Publish**.
4. Обновите приложение. Если чаты не открываются — проверьте, что структура `chats/{id}/members` и `channels/{id}/members` в базе действительно существует: именно по ней теперь проверяется доступ.

## Кто что может

| Узел | Чтение | Запись |
|---|---|---|
| `messages/{chatId}` | только участники: для `dm_…` — по uid в id чата; для группы/канала — `members/{uid}` | отправитель своего сообщения; участник может поставить `readBy/{свой uid}`, реакцию и голос в опросе |
| `media/{chatId}/{msgId}` | только участники чата | автор вложения (`uid` внутри записи) |
| `typing_v2/{chatId}/{uid}` | только участники чата | только свой `uid` |
| `calls/{callId}` | только `callerId` и `calleeId` | только участники звонка, SDP ≤ 60 КБ |
| `call_inbox/{uid}` | только владелец | владелец или звонящий (`callerId`) |
| `user_chats/{uid}` | только владелец | владелец; превью для собеседника в DM, для участников группы и для админов канала |
| `reports` | админы; пользователь — только свои жалобы и жалобы на себя | только от своего имени, нельзя на себя |
| `bans` | админ или сам пользователь | админ; автоматически — только при ≥4 реальных жалобах и корректном сроке |
| `ban_history` | админ или сам пользователь | только админ |
| `gift_wallet/{uid}/balance` | авторизованные | владелец; другой пользователь может только **пополнить** баланс (не уменьшить) |
| `gift_inventory/{uid}/{item}` | авторизованные | владелец или передача с `fromUid = auth.uid` и `toUid = uid` |
| `gift_transfers/{id}` | авторизованные | только создание от своего имени |
| `gift_quiz_claims/{uid}/{day}` | только владелец | только владелец |
| `stories/{id}` | авторизованные | автор истории; зритель может поставить `views/{свой uid}` и лайк |
| `story_media`, `story_comments`, `channel_comments` | авторизованные | автор записи; историю/канал может чистить владелец |
| `galochka` | авторизованные | **никто из клиента** — только Firebase Console |
| `shops/{uid}`, `shop_orders`, `shop_reviews` | авторизованные | продавец — свой магазин; покупатель — свой заказ; отзыв — только покупатель заказа |

Дополнительно:

- **Бан** проверяется в правилах на записи в `messages`, `media`, `stories`, `story_comments`, `channel_comments`, `calls`. Забаненный аккаунт не сможет писать даже через SDK.
- **Размеры**: текст сообщения ≤ 20 000 символов, фото ≤ 900 000, файл ≤ 1 500 000, голос ≤ 800 000, кружок ≤ 1 500 000 символов base64. Слишком большое вложение отклоняется правилами.
- **Автобан**: срок 1 день; 30 дней — только если в `reports/{uid}` реально ≥ 8 жалоб. Клиентский счётчик больше не учитывается.
- `messages/{chatId}` целиком может удалить только владелец группы или канала (очистка истории при удалении).

## Что ещё нужно для полной защиты

Правила RTDB не могут подтвердить оплату и не могут вести баланс «умов»: клиент всё ещё начисляет умы за тесты, крафт и продажу подарков. Правила запрещают менять чужой баланс и ограничивают суммы, но чтобы валюта не накручивалась своим же клиентом, нужен серверный ledger в Cloud Functions:

- `payOrder` — транзакция: списать у покупателя, начислить продавцу, создать заказ, записать журнал операций и защиту от двойного списания;
- `claimQuiz`, `craftGift`, `sellGift` — начисления только на сервере;
- `turnCredentials` — временные TURN-креды для звонков (сейчас только STUN, поэтому звонки могут не проходить в мобильных сетях и за NAT);
- FCM-push, Firebase Storage для вложений, Sentry — требуют отдельных ключей и деплоя.

Это следующий этап: он требует плана Blaze и `firebase deploy --only functions`.
