# Firebase Rules MetroChat — разбор присланного полного JSON

Спасибо, теперь есть полный объект `rules`. В нём присутствуют необходимые для текущих сценариев узлы: `user_chats`, `messages`, `stories`, `story_media`, `gift_inventory`, `gift_transfers`, `gift_wallet`, `gift_earn`, `gift_quiz_claims`, `galochka` и `user_settings`.

## Почему витрина подарков могла не открываться

В коде была ошибка порядка экспорта: `renderGiftShop` сначала экспортировалась в `window`, а затем заменялась новой реализацией. Динамические `onclick="renderGiftShop()"` могли вызывать устаревшую функцию. В патче переэкспортирована финальная функция после всех переопределений. Дополнительно загрузка баланса теперь обрабатывается отдельно: ошибка чтения не ломает отрисовку витрины и не превращается в нулевой баланс.

В предоставленных Rules есть разрешения чтения/записи для `gift_inventory`, `gift_transfers`, `gift_wallet/$uid/balance`, `gift_earn/$uid` и `gift_quiz_claims`. Для обычного вошедшего пользователя этих путей достаточно, чтобы клиентские операции витрины выполнялись по текущей схеме.

## Важные проблемы безопасности в текущих Rules

Текущие правила очень широкие. Не заменяйте их вслепую, но запланируйте отдельную миграцию:

1. `user_chats`, `messages`, `stories`, `story_media`, `calls`, `media`, `typing` и ряд других узлов разрешают `.read` и/или `.write: auth != null`. Это даёт любому вошедшему пользователю возможность читать/изменять чужие данные.
2. `galochka` имеет `.write: auth != null`. Любой авторизованный пользователь может попытаться изменить статус подтверждения. Запись должна выполняться доверенным сервером/администратором.
3. `gift_inventory` и `gift_transfers` имеют `.write: auth != null`. Это позволяет подделывать и менять инвентарь/записи переводов других пользователей.
4. `gift_wallet/$uid/balance` разрешает владельцу менять свой баланс, а любому вошедшему пользователю — увеличивать его, если `newData >= data`. Это не защищает от поддельного начисления УМ.
5. `channels` и `channel_comments` также содержат широкие права. Нужна отдельная проверка ролей владельца, администраторов и подписчиков.

## Почему я не подменил Rules автоматически

В клиенте ещё есть прямые записи баланса при начислениях, бустах, заказах и покупках. Если просто закрыть `.write`, часть функций сразу перестанет работать. Правильное исправление — сначала перенести все денежные операции и передачу подарков в Cloud Functions с проверкой баланса и получателя, затем сузить Rules и проверить два аккаунта в Rules Simulator.

**Сейчас не очищайте базу и не заменяйте полный JSON случайным шаблоном.** Клиентский патч не требует расширять присланные разрешения.
